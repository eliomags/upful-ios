# Upful iOS App -- Comprehensive Feature-by-Feature Analysis

## Application Overview

Upful is a stock screening, analysis, and simulated trading iOS application. It provides users with tools to screen stocks by financial criteria, view detailed stock data (quotes, financials, charts), manage a simulated portfolio with a $25,000 starting balance, save stocks and screeners, read market news, and compare stocks on various metrics. The app monetizes through a single monthly subscription ("Premium") that gates access to advanced features like unlimited screening and five-year historical data.

### Screen Purpose
The Home screen is the portfolio dashboard. It serves as the main landing screen after the splash animation. It shows the user's simulated trading portfolio: total equity, cash balance, individual holdings with per-stock profit/loss, a pie chart breakdown of the portfolio, and preference-based stock suggestions.

### User Stories and Flows
1. **View portfolio summary**: User sees total equity vs. the $25,000 initial balance at the top, along with current cash balance and a "last updated" timestamp.
2. **View individual holdings**: Each holding row shows ticker, number of shares, current price, average cost basis, dollar change, and percentage change. Color-coded green/red for gain/loss.
3. **Interact with holdings**: Long-press a holding to get a context menu with "View" (navigate to stock detail), "Trade" (open trade screen), or "Sell All" (sell entire position).
4. **View portfolio breakdown**: A collapsible pie chart section shows the distribution of holdings plus cash balance using a donut chart.
5. **Receive stock suggestions**: Based on user preferences (industry, growth, profitability, dividend), the app screens stocks and shows up to 3 random suggestions per preference group.
6. **Pull to refresh**: Holdings auto-refresh on a 15-second timer, and the user can also pull to refresh.
7. **Navigate to screener**: A "Screener" button in the nav bar pushes to the screener selection screen.
8. **First-time experience**: On first launch, the splash screen plays, then a subscription prompt appears.

### UI Components
- **UITableView** (grouped style) with 3 sections: Holdings, Breakdown (pie chart), Suggestions
- **TradingBalanceView** as table header: contains TotalEquityView and CashBalanceView in a horizontal stack
- **StockHoldingTableViewCell**: Custom cell with ticker label, shares label, current/average price labels, dollar/percent change labels
- **HoldingsBreakdownTableViewCell**: Contains GenericPieChartView (Charts library, donut style with 62% hole radius)
- **HoldingBreakdownHeaderView**: Collapsible section header with chevron toggle animation
- **HomeFeedAuxiliaryActionView**: Horizontal row of action buttons (Preferences, Suggestions, Upgrade)
- **SentimentView**: Pill-shaped view showing Positive/Negative/Neutral sentiment for news

### View Hierarchy and Layout
100% programmatic UIKit. No storyboards. All views use Auto Layout constraints via a custom `anchor(top:leading:bottom:trailing:padding:size:)` extension method. The table view fills the safe area.

### Navigation Patterns
- **Coordinator pattern**: `NewsCoordinator` pushes `NewsViewController` onto the navigation stack.
- **Direct navigation**: The home VC directly pushes the screener selection or stock detail screens.
- **Modal presentation**: Subscription and preferences are presented modally via their respective Presenter classes.
- Context menus use `UIContextMenuConfiguration` for inline actions.

### Data Flow
- `HomeGeneralLogicController` owns the business logic. It uses `TradingEngine.shared` (singleton) to load holdings via a completion handler.
- Holdings auto-refresh on a 15-second `Timer`.
- Preferences are loaded via `PreferenceDataManager.getGroupedPreferences()`, which returns Core Data-persisted preferences.
- For each preference group, `StockScreeningService` is called to fetch matching stocks from the Intrinio API.
- News is loaded via `NewsLoader` from stocknewsapi.com.
- State management uses a `SectionState` enum (`new`, `empty`, `loading`, `loaded`, `error`) per section, with closure callbacks (`holdingsStateChanged`, `suggestionsStateChanged`).

### Trading Engine
- `TradingEngine.shared` is a singleton managing the simulated portfolio.
- `BalanceManager` tracks cash balance (starting at `BalanceConstants.initialCash` = $25,000).
- Holdings are loaded asynchronously; the home screen compares total equity against the initial $25,000 to show net gain/loss.
- "Sell All" creates a transaction and calls `tradingEngine.sell()`.

### Current State

- The pie chart is functional with cycling colors from a predefined palette.
- The suggestions feature works but is limited to 3 randomized results, which may feel sparse.

### UX Issues / Gaps

- **Hardcoded API key** in `StockScreeningService.swift` (`OjNiMzRkZmFlNDBkYjIzYTgyMTNhNjcyZGNlZmYzMjE1`). This is a security concern -- API keys should be stored server-side or in a secure configuration.

## Cross-Cutting Architecture Summary

### Architectural Patterns
| Pattern | Usage |
|---------|-------|
| **MVVM-like with Logic Controllers** | Logic controllers act as view models with state machines and closure-based callbacks |
| **Coordinator** | Navigation encapsulated in coordinator classes (StockDetailsCoordinator, SearchResultsCoordinator, etc.) |
| **Presenter** | Modal presentation logic encapsulated in presenter structs (SubscriptionPresenter, ReportPresenter, FeaturePresenter, StockComparisonPresenter) |
| **Singleton** | TradingEngine.shared, PermissionManager.shared, AnalyticsLogger.instance, PersistenceService |
| **Protocol-oriented** | Service protocols (IAPServiceProtocol, QuoteLoader, StockScreener, SuggestionsLoaderProtocol, etc.) for dependency injection |
| **State machine** | Enum-based states (new/loading/loaded/empty/error) with didSet observers |

### Technology Stack
| Technology | Purpose |
|------------|---------|
| UIKit (programmatic) | All UI -- no storyboards |
| Core Data | Persistence for SavedStock, SavedScreener entities |
| StoreKit (v1) | In-app purchases |
| Charts (danielgindi) | Pie, bar, and line charts |
| YSDraggy | Bottom-sheet drag interaction |
| Kingfisher | Image loading/caching |
| SFSafariViewController | In-app web browsing |
| MessageUI | Email composition |

### API Dependencies
| API | Endpoint | Purpose |
|-----|----------|---------|
| Intrinio | api.intrinio.com | Stock screening, financial data, descriptions |
| StockNewsAPI | stocknewsapi.com | Market and ticker news |
| Remote Screener/Suggestion Source | (likely Firebase/Firestore) | Prebuilt screeners, popular stocks, suggestions |

### Global UX Issues Summary
1. **Hardcoded API key** in StockScreeningService -- security vulnerability.
2. **Force-unwraps and fatalError** in production code paths.
3. **No offline mode** -- the app is entirely dependent on network connectivity with minimal error recovery.
4. **Inconsistent error handling** -- some screens show alerts, others silently fail.
5. **No accessibility** considerations observed (no VoiceOver labels, dynamic type limited).
6. **Reorder persistence is destructive** (delete-all-and-re-save pattern).
7. **Singleton-heavy architecture** makes unit testing difficult.
8. **NPS survey triggers App Store review for detractors** (scores 0-6).
9. **Tracking opt-out gated behind paywall** -- potential privacy/compliance concern.
10. **"New Group" folder name** for StockTrade indicates incomplete project organization.
