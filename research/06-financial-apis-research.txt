4. YAHOO FINANCE (Unofficial APIs & Libraries)
================================================================================

Website:        https://finance.yahoo.com
Libraries:      yfinance (Python), yahoo-finance-api (Node.js)
NPM Package:    yahoo-finance2 (Node.js/TypeScript)
Swift Package:  YahooFinanceAPI (community)

RATE LIMITS (Unofficial - no formal API):
  - No official API or rate limits
  - Community consensus: ~2,000 requests/hour before throttling
  - IP-based rate limiting (no API key)
  - Can be more aggressive with rotating user agents
  - Yahoo may block aggressive scraping

DATA COVERAGE:
  [x] US Stocks (NYSE, NASDAQ, AMEX)       - 15-min delayed quotes
  [x] International Stocks                  - 70+ global exchanges
  [x] Forex                                 - Major and minor pairs
  [x] Cryptocurrency                        - Major coins
  [x] ETFs                                  - Comprehensive US and intl
  [x] Mutual Funds                          - NAV data, holdings, performance
  [x] Bonds                                 - Treasury yields, some corporate
  [x] Options                               - Full options chains
  [x] Futures                               - Commodity and financial futures
  [x] Company Fundamentals                  - Full financials, balance sheet,
                                              income statement, cash flow,
                                              key statistics, analyst estimates
  [x] Market News                           - Via yahoo news feed
  [x] Indices                               - All major global indices
  [x] Historical Data                       - Full history (decades)
  [ ] Economic Data                         - Limited
  [ ] Real-time streaming                   - NOT available (unofficial)

DATA DELAY:
  - US Stocks: 15-minute delayed
  - International: Varies (15min to EOD depending on exchange)
  - Crypto: Near real-time
  - Options: 15-minute delayed

AUTHENTICATION: None (no API key needed)
  - However, some endpoints require cookies/crumb tokens
  - yahoo-finance2 npm package handles this automatically

API QUALITY: MODERATE
  - Unofficial and can break without notice
  - No SLA or support
  - Libraries handle most complexity
  - Data quality is generally good (sourced from exchanges)
  - Endpoints change occasionally

INTERNATIONAL COVERAGE: EXCELLENT
  - One of the best free sources for international data
  - Covers virtually every major exchange globally
  - Supports exchange-specific suffixes (e.g., .L for London,
    .T for Tokyo, .HK for Hong Kong, .SS for Shanghai)

EXCHANGE SUFFIXES:
  - .L    = London Stock Exchange (LSE)
  - .T    = Tokyo Stock Exchange (TSE)
  - .HK   = Hong Kong Stock Exchange (HKEX)
  - .SS   = Shanghai Stock Exchange (SSE)
  - .SZ   = Shenzhen Stock Exchange (SZSE)
  - .TO   = Toronto Stock Exchange (TSX)
  - .DE   = Frankfurt/XETRA
  - .BO   = Bombay Stock Exchange (BSE)
  - .NS   = National Stock Exchange India (NSE)
  - .AX   = Australian Securities Exchange (ASX)
  - .PA   = Euronext Paris
  - .AS   = Euronext Amsterdam
  - .MI   = Milan/Borsa Italiana
  - .KS   = Korea Stock Exchange
  - .TW   = Taiwan Stock Exchange
  - .SA   = Sao Paulo (B3)
  - .MX   = Mexican Stock Exchange
  - .JK   = Jakarta Stock Exchange
  - And many more...

GOTCHAS & LIMITATIONS:
  - UNOFFICIAL: Can break at any time without notice
  - Yahoo has deprecated official APIs multiple times
  - Aggressive scraping may lead to IP blocking
  - Need to handle cookie/crumb authentication
  - No guaranteed uptime or data accuracy SLA
  - Some endpoints require additional headers
  - Rate limits are enforced per-IP, not per-key
  - Mobile app may use different endpoints than web

AVAILABLE LIBRARIES (for iOS/Swift integration):
  - yahoo-finance2 (Node.js): Most maintained, TypeScript support
  - yfinance (Python): Most popular, well-maintained
  - YahooFinanceAPI (Swift): Community package, less maintained
  - Can also hit Yahoo Finance endpoints directly via URLSession

VERDICT FOR PAPER TRADING APP:
  - BEST overall free data source for breadth of coverage
  - Covers nearly every asset type and exchange globally
  - Only free source with options chains and mutual funds
  - Risk: unofficial, could break
  - RECOMMENDATION: Use as PRIMARY data source, with fallbacks

Since this is an iOS app, the most relevant library access patterns:

--- FOR iOS (Swift) ---

Direct HTTP Access:
  URL Pattern: https://query1.finance.yahoo.com/v8/finance/chart/{symbol}
  URL Pattern: https://query2.finance.yahoo.com/v10/finance/quoteSummary/{symbol}

  These endpoints require:
  - A valid "crumb" token (obtained from cookie)
  - Cookie header from initial yahoo.com visit

  Parameters:
  - range: 1d, 5d, 1mo, 3mo, 6mo, 1y, 2y, 5y, 10y, ytd, max
  - interval: 1m, 2m, 5m, 15m, 30m, 60m, 90m, 1h, 1d, 5d, 1wk, 1mo, 3mo
  - modules: assetProfile, incomeStatementHistory, balanceSheetHistory,
             cashflowStatementHistory, defaultKeyStatistics, financialData,
             calendarEvents, recommendationTrend, upgradeDowngradeHistory,
             institutionalOwnership, earningsHistory, earningsTrend,
             industryTrend, price, summaryDetail, summaryProfile

--- FOR BACKEND (Node.js) ---

npm package: yahoo-finance2
  - Handles crumb/cookie automatically
  - TypeScript support
  - Methods: quote(), quoteSummary(), historical(), search(),
             options(), insights(), recommendations()

--- FOR BACKEND (Python) ---

pip package: yfinance
  - Most popular Yahoo Finance library
  - Handles authentication automatically
  - Methods: download(), Ticker(), info, history, options,
             financials, balance_sheet, cashflow

RATE LIMITS (all unofficial):
  - ~2,000 requests/hour per IP
  - Throttling increases with volume
  - No official documentation
  - Rotating IPs or adding delays helps

VERDICT FOR PAPER TRADING APP:
  - Build a thin backend service that uses yahoo-finance2 (Node.js)
  - Cache responses aggressively (data is delayed anyway)
  - iOS app hits your backend, not Yahoo directly
  - RECOMMENDATION: Use via backend proxy with aggressive caching

27. IMPLEMENTATION STRATEGY
================================================================================

ARCHITECTURE:
  iOS App <-> Backend API (Node.js) <-> Multiple Data APIs
                                    <-> Cache Layer (Redis/SQLite)

WHY A BACKEND:
  1. Yahoo Finance requires cookie/crumb handling (hard in iOS)
  2. Aggregate multiple API sources into unified response
  3. Cache data aggressively (15-60 min delay is acceptable)
  4. Manage API keys server-side (security)
  5. Rate limit management and request queuing
  6. Transform data into consistent format

CACHING STRATEGY (critical for staying within free limits):
  - Stock quotes: Cache 15 minutes
  - Fundamentals: Cache 24 hours
  - Economic data: Cache 6-12 hours
  - News: Cache 30 minutes
  - Historical data: Cache indefinitely (immutable)
  - Crypto: Cache 5-10 minutes
  - Options chains: Cache 15 minutes
  - Exchange rates: Cache 1 hour

ERROR HANDLING & FALLBACK CHAIN:
  For stock quotes:
    1. Try Yahoo Finance
    2. Fall back to Finnhub
    3. Fall back to Twelve Data
    4. Return cached data with staleness indicator

  For crypto:

  For economic data:
    1. Try FRED

HIGH RISK (may break or change terms):

  - Stooq: Unofficial scraping source

MEDIUM RISK (free tier may be reduced):
  - Alpha Vantage: Already reduced from 500 to 25/day
  - CoinGecko: Tightened limits in 2024-2025
  - IEX Cloud: Underwent ownership changes
  - Marketstack: Free tier nearly useless already

LOW RISK (stable free tiers):
  - Finnhub: Consistently generous free tier
  - FRED: Government-funded, always free
  - ECB API: Government-funded, always free
  - US Treasury: Government-funded, always free
  - SEC EDGAR: Government-funded, always free
  - Binance: Public data always free
  - OpenFIGI: Bloomberg-backed standard
  - World Bank: Always free

MITIGATION STRATEGY:
  1. Always have 2+ data sources for critical data types
  2. Cache aggressively to reduce API dependency
  3. Design backend with provider abstraction layer
  4. Monitor API changes via provider blogs/changelogs
  5. Keep Yahoo Finance as primary but prepare for it breaking
  6. Government APIs (FRED, SEC, Treasury) are the most reliable
